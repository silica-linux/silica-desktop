# M1.5 · Dock prototype: Flutter against Rust

Gate 1 decides which toolkit the shell is written with. Instead of estimating it, M1.5 builds
the same part of the shell twice and measures it: the Dock with the magnification under the
pointer, the most animated and most visible part.

The options the gate has to choose from:

| Option | Shell | Apps |
| --- | --- | --- |
| A | Flutter, custom embedder | Flutter, custom embedder |
| B | Rust (iced, separate layer-shell processes) | Flutter, custom embedder |
| C | Flutter, official GTK embedder | Flutter, official GTK embedder |

C remains as a fallback: it is not prototyped.

## The Dock, the same in both versions

The two versions follow the same specification, so the measurements are comparable and the
screenshots can be overlaid.

- Layer-shell surface at the bottom, anchored left, right and bottom, 160 logical px tall,
  exclusive zone 72 px, no keyboard, transparent background.
- 12 icons generated in code: rounded squares (radius 22% of the side) with a vertical
  gradient from a hue (in order: 0°, 30°, … 330° in HSL, saturation 70%, lightness 60%) to
  the same hue with lightness 40%, no assets.
- Icon at rest 48 px, spacing 8 px. Background: white rounded rectangle at 25%,
  radius 18 px, inner margin 8 px, 8 px from the bottom edge; at rest it is 680 px wide.
- Magnification: with the pointer at distance `d` from the icon's center at rest, measured
  in steps of 56 px (icon + spacing), `bump(d) = (1 + cos(π·d/3))/2` for `d < 3`,
  otherwise 0; icon scale `1 + m·bump(d)`, at most 2×. The icons grow upwards with the base
  aligned; the row and the background stay centered in the surface.
- `m` goes from 0 to 1 when the pointer enters and from 1 to 0 when it leaves, with a spring
  (mass 1, stiffness 400, damping 30, that is underdamped); after leaving, the shape of the
  magnification stays that of the last pointer position. This way there is an animation even
  without movement.
- Label of the icon nearest to the pointer (`App 1` … `App 12`), Inter 13 px white,
  on a black pill at 63% (radius 6 px, margin 8×4 px), 8 px above the icon.
- Click: no action in the prototype.

## Tasks

- **M1.5.1 · OpenGL renderer in the embedder.** EGL + `wl_egl_window` with
  `FlutterOpenGLRendererConfig`; `--renderer gl|software`, software stays the default for
  the headless tests (headless Ossido uses Pixman and does not offer EGL to the clients).
- **M1.5.2 · Measurements in Ossido, the same for every toolkit.** Command `perf.frames`: for
  every surface, intervals between commits with a buffer (mean, p50, p95, p99, maximum,
  frames over 1.5 periods). Command `perf.process`: PSS and RSS from
  `/proc/<pid>/smaps_rollup` (pid from the client's credentials) and the time from startup to
  the first buffer.
- **M1.5.3 · Dock in Flutter.** `apps/dock`, on top of the embedder with the GL renderer.
- **M1.5.4 · Dock in Rust.** `crates/dock-iced`, iced 0.14 with `iced_layershell` 0.19
  (both MIT). The crate is a prototype: if B wins it becomes the base of the shell, if
  A wins it is deleted.
- **M1.5.5 · Test bench.** `cargo xtask bench dock`: starts Ossido nested at
  2560×1600 (scale 2), then each Dock in turn, cold and warm; moves the pointer back and
  forth over the Dock at 120 events/s for 10 s with `input.pointer_move`, then moves it out
  to measure the spring; collects `perf.frames`, `perf.process` and two screenshots (rest,
  magnified). Three runs, the median is reported.
- **M1.5.6 · Report.** `docs/gate1-dock.md`: table of the measurements, screenshots side by
  side, lines of code and hours for each version, recommendation. Then gate 1.

## Proposed thresholds

To be confirmed at the gate; the memory limit is set by the user.

| Metric | Threshold |
| --- | --- |
| Frames over 1.5 periods during the scroll | < 1% |
| p99 interval | ≤ 1.5 refresh periods |
| First frame of the animation after startup | no interval over 50 ms |
| Dock memory (PSS) | to be set |
| Startup to the first buffer | to be reported, no threshold |

## Limits of the measurements

- WSLg: GL goes through Mesa d3d12 to the Windows GPU and the refresh is that of the nested
  window. The numbers hold for the comparison between the two versions, not as absolute
  values. Confirmation on real hardware comes with M6.
- The Flutter Dock runs in its own process. If A wins, the shell will use a single engine
  for several surfaces (multi-view): the memory measured here is an upper bound for the Dock
  but a lower bound for the whole shell.
- The development hours are recorded by the agent writing the prototypes: they are an
  indication, not a measurement.
